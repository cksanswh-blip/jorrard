## B. DESIGN.md 컬렉션 (이게 무료 중 가장 실속)

레퍼런스 MCP가 결국 내주는 것이 DESIGN.md다. 그 완제품이 공개돼 있다.

### B-1. awesome-design-md (VoltAgent, MIT) · **8개 저장 완료**

- 73개 실제 사이트 DESIGN.md. 9절 구조(분위기 · 색 역할 · 타이포 · 컴포넌트 · 레이아웃 · 깊이 · Do/Don't · 반응형 · 에이전트 프롬프트). Google Stitch가 정의한 DESIGN.md 형식을 따른다.
- 이 세션에서 **73개 전부 내려받아 훑고, 오랑에 맞는 8개만 저장**했다. 선정 기준은 흰·크림 캔버스 + 단일 따뜻한 강조색 + 정보 밀도 또는 에디토리얼. 목록과 이유는 `reference/awesome-design-md/INDEX.md`.
- 특히 **Intercom**(크림 화이트에 오렌지 하나만 CTA에 예약)이 우리 "흰 배경 + 오렌지 포인트" 원칙의 가장 가까운 실물이다. **PostHog**는 크림 캔버스에 데이터 밀도, **Notion**은 구독 화면의 4단 가격표, **Wired**는 소식글 읽기 경험.

### B-2. oh-my-design (kwakseongjae, MIT) · 한국 개발자 프로젝트

- `npx oh-my-design-cli@latest` 한 줄로 Claude Code에 스킬 22종 + 서브에이전트 19종 + **440개+ 품질 등급 기업 레퍼런스** 설치. API 키·MCP 서버 불필요. 한국어 README 있음.
- **Toss·당근(Karrot) 같은 한국 서비스 레퍼런스가 카탈로그에 있다.** 한국 사용자 대상 UI 관용구(가격 표기·약관·본인인증 흐름)는 해외 컬렉션엔 없는 것이라 구독·결제·온보딩 화면에 값이 크다.
- 주의: 설치 범위를 **Project**로 두면 이 저장소 `.claude/` 아래에 파일이 대량 생긴다. 이 저장소가 아니라 별도 작업 폴더에서 돌리거나 `--global`로.
- 카탈로그 사이트(oh-my-design.kr)는 이 환경에서 차단돼 내용은 못 봤다. npm 패키지 존재(v2.0.0)와 README만 확인.

### B-3. awesome-claude-design (rohitg00, MIT)

- Claude Design(2026-04 출시)용 DESIGN.md 프롬프트를 **미학 계열별**로 묶은 것. Editorial Minimalism · Warm Editorial · Data-Dense Pro 등. 오랑은 "Warm Editorial + Data-Dense" 교차점이라 두 계열의 프롬프트 팩이 바로 쓰인다.
- 커뮤니티 경고 한 줄: Claude Design은 토큰을 많이 쓴다(2~3 프롬프트에 주간 한도 소진 보고). 우리는 Claude Design이 아니라 DESIGN.md 텍스트만 가져다 쓰면 된다.

## C. Anthropic 공식 `frontend-design` 스킬 · **설치 완료**

- `anthropics/skills` 저장소의 스킬. Apache 2.0. `.claude/skills/frontend-design/`에 SKILL.md + LICENSE.txt를 넣었다. 이 저장소를 cwd로 열면 자동 로드된다.
- 요지: 템플릿 기본값을 거부하고 **주제에서 시각 결정을 끌어낸다**. 타이포 1~2 패밀리, 줄 길이 80자 이하, 구조선은 장식이 아니라 정보, 모션은 절제, 카피는 능동태. **대표님 취향(디테일·여백·위계·절제된 강조)과 거의 같은 방향**이라 충돌이 없다.
- 쓰는 법: 화면 제안서를 쓸 때 "frontend-design 스킬을 적용해 design/DESIGN.md 제약 안에서 A안/B안"이라고 지시.

## D. 자기 사이트를 재는 MCP (제1법 제8조 검증에 직결)

레퍼런스는 "남의 것"이고, 제1법이 요구하는 검증은 "우리 것"을 재는 일이다. 이 둘은 다른 도구다.

| 서버 | 무엇 | 왜 필요한가 |
| :-- | :-- | :-- |
| **Chrome DevTools MCP** (Google 공식, Apache 2.0, `chrome-devtools-mcp@latest`) | 라이브 크롬 제어. 성능 트레이스·스크린샷·네트워크·콘솔 | 제8조의 "실클릭 · 스크린샷 · getComputedStyle · 콘솔 0"을 에이전트가 직접 한다. 캘린더 콜드 렌더 2초 같은 수치 검증. 쿼리스트링 없는 URL로 잴 것(86행) |
| **Playwright MCP** (Microsoft 공식, Apache 2.0, `@playwright/mcp@latest`) | 접근성 트리 기반 브라우저 조작 | 로그인/로그아웃 양쪽 상태를 스크립트로 재현. 6표면 회귀 확인. README가 "코딩 에이전트는 CLI+스킬이 토큰 효율이 낫다"고 안내하므로 반복 검증은 `playwright-cli`도 검토 |

둘 다 `.mcp.json`에 넣었다. 로컬 크롬이 필요하다. **iframe(srcdoc) 안 요소를 잡을 때 첫 번째 iframe을 잡지 말고 srcdoc 속성으로 특정**한다(제10-1조).

## E. UI 생성: Google Stitch (월 350회 무료)

- Google Labs의 Stitch가 프롬프트에서 화면·HTML/CSS·DESIGN.md를 생성한다. 무료 350회/월, 유료는 2026-Q4 예정.
- MCP 경로가 셋이다. ① 공식 문서 `stitch.withgoogle.com/docs/mcp/setup/`(차단돼 못 읽음, 검색 요약은 `@google/stitch-mcp`라 했으나 **npm에 없다**) ② `stitch-mcp`(Kargatharaakash, Google Cloud 프로젝트 + gcloud 인증) ③ `@_davideast/stitch-mcp`(v0.9.0, Apache 2.0, `STITCH_API_KEY` 또는 gcloud). 둘 다 비공식.
- 판단: **오랑에는 후순위.** 우리는 기존 자산을 100% 유지하며 고도화하는 것이지 새 화면을 생성하는 것이 아니다(제1조 1항). 다만 **구독·결제 화면(신설)** 초안 3안을 빠르게 뽑는 데는 쓸 만하다. Google Cloud 인증이 필요해 대표님이 켤지 정한다.

## 무료만으로 짜는 착수 순서 (돈 0원)

1. **지금 바로**: `reference/awesome-design-md/` 8개 + `design/DESIGN.md` 대조표를 만든다. MCP도 계정도 필요 없다. 첫 화면은 메인 피드, 대조 상대는 Intercom·PostHog·Airbnb.
2. **로컬 5분**: `claude mcp list`로 refero·inspo·chrome-devtools·playwright 4개가 connected인지 확인. 안 되는 것은 README §1의 명령으로 재등록.
3. **로컬 10분**: `npx oh-my-design-cli@latest --global` 로 한국 레퍼런스 카탈로그 확보. Toss·당근 DESIGN.md를 구독·결제 화면 대조에 쓴다.
4. Lazyweb은 설치 후 **무료 플랜에서 검색 데이터가 실제로 오는지 1회 확인**하고 유지 여부 결정.
5. 유료 3종은 위 넷을 한 바퀴 돌고 나서도 부족한 것(모바일 앱 플로우 스크린샷 대량)이 있을 때만.
